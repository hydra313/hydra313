# Build decisions and deferred items

Decisions made during the build of the auction deal finder (plan: docs/superpowers/plans/2026-10-22-auction-deal-finder.md), copied from the build ledger. Each "Ruling" is a call made where the spec or plan was silent or conflicted; "minor (deferred)" lines are known small issues left for later.

## Rulings

- Ruling 1: Catalog.mask_patterns() returns the `match` of ALL platforms (enabled or not) and nothing else — platform names already cover every console name, and bulk patterns swallow unit words — cost if wrong: some model-number false quantities slip through; caught by T7 tests.
- Ruling 2: parse_quantity's unit-word form allows up to 3 intervening tokens (words or "_") between the count and the unit, and accepts PLURAL unit words only (consoles, systems, controllers, games, carts, cartridges, discs, units, pcs, pieces, gpus, cpus, cards, processors) — keeps "Spider-Man 2 PS5 Console Bundle" = 1 while "3 Nintendo Switch 2 consoles" = 3 — cost if wrong: a few odd titles misparse; covered by added test rows.
- Ruling 3: masking replaces the UNION of all match spans of all mask patterns (merged, not applied sequentially), so the longest overlapping name wins — cost if wrong: overlapping platform names leak digits.
- Ruling 4: budget.py holds a module-level `SCAN_LOCK = threading.Lock()`; `Budget.lock` returns it, so every Budget instance shares one lock — cost if wrong: none significant (single-process app).
- Task 1: Ruling: reviewer asked for `scan_enabled` in Config — scan_enabled is a runtime DB setting per spec §13 (default false via Budget), not a Config field; strict unknown-key rejection is kept (catches typos) — cost if wrong: a user putting scan_enabled in config.yaml gets a clear error.
- Task 1: Ruling: add Config fields market_ttl_hours=24, item_price_ttl_days=30, min_comps=5, min_item_comps=3 (Global Constraints values) — cost if wrong: none.
